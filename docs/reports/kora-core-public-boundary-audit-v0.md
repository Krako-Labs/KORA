## Claim Boundary Audit

### Supported Statements

The branch may state:

- KORA makes AI workloads routable.
- KORA Core is the planned open-source AI workload execution layer.
- KRK is the deterministic-first routing kernel inside KORA Core.
- The current public implementation is KRK-oriented.
- Current evidence includes a bounded deterministic-heavy benchmark.
- The KRK extended matrix and GPU-routed subset work are methodology or planned measurement unless measured values are explicitly present.

### Approved Benchmark Wording

Use:

> In a reproducible 100-task deterministic-heavy benchmark workload, KORA-controlled execution avoided 80 of 100 simulated model invocations versus a naive direct baseline.

Required qualifiers:

- deterministic-heavy.
- simulated model invocations.
- naive direct baseline.
- bounded alpha evidence.

### Unsupported Statements

The branch should not state or imply:

- production readiness.
- broad workload superiority.
- provider replacement.
- model serving replacement.
- infrastructure reduction.
- final competition result.
- formal external validation.
- 10x savings.
- customer-level savings.

## Naming Consistency Audit

### KORA

Consistent meaning:

- umbrella and movement.
- north star: make AI workloads routable.

### KORA Core / KC

Consistent meaning:

- planned open-source AI workload execution layer.
- future workflow: inspect, compare, run, report.

Boundary:

- Docs should not imply all future KORA Core workflow commands are implemented.

### KRK

Consistent meaning:

- KORA Routing Kernel.
- deterministic-first execution routing kernel inside KORA Core.
- routes across deterministic, cache, CPU, provider, GPU, and fallback paths.

### Krako

Consistent meaning:

- future commercial infrastructure company context.
- separate from OSS KORA claims unless explicitly approved.

## Known Limitations

- Current top-level CLI exposes example-oriented commands, not every documented KRK primitive as a top-level command.
- Extended KRK matrix metrics are not measured yet.

- Provider-backed validation remains future work.
- Historical repo docs still contain broad-scan matches that predate this branch.
