# Foundation and Research Foundry Alpha implementation

## Summary

This change adds public, local-first primitives for device visibility, capability and fleet records, measurement/evidence contracts, optional MLX and llama.cpp adapters, and Research Foundry Alpha. Research Foundry performs deterministic text-layer PDF ingest, exact SHA-256 deduplication, page-aware chunking, unchanged-content reuse, SQLite FTS5 retrieval, and evidence-card rendering.

## Public surface

- `kora system inventory`, `fleet`, `reality`, `package`, and `evidence` commands
- strict Foundation inventory, capability, measurement, lineage, and evidence-registry contracts
- fail-closed `mlx_local` and `llama_cpp_local` adapters for explicitly configured local runtimes
- `kora research ingest` and `kora research query`
- optional `research` dependency extra containing only `pypdf>=6,<7`
- focused Foundation, adapter, Research Foundry, and CLI tests

## Evidence and safety boundaries

Device and capability records are detected metadata, not runtime compatibility or performance evidence. Measurement plans contain no results. Artifact verification establishes byte integrity and lineage, not measurement correctness. Registry counts do not rank hardware, runtimes, or topologies.

Research Foundry evidence cards contain retrieved excerpts and provenance only. The implementation provides no OCR, vector database, semantic synthesis, factuality proof, output-quality proof, cloud fallback, or production-readiness evidence. Tests use generated fixtures and do not establish broader workload representativeness.

The added Research path performs no model call, provider call, network request, or upload. Local adapters run only when explicitly selected and configured; they do not download models or fall back to a provider. No raw PDFs, databases, model files, runtime outputs, credentials, or local absolute paths are part of this change.
